All notable changes to Pi Daemon are documented here. The project follows
semantic versioning once a release tag is cut.

- make every root `web:*` npm wrapper preserve forwarded workspace-tool arguments through a bounded Node exec seam that inserts the inner `--` explicitly, so focused `--grep`/reporter flags and multiword values cannot be consumed as npm configuration and silently broaden a run
- give the Vitest web suite a supported passing-test diagnostic channel: `reportTestDiagnostic` writes one bounded line through stderr (with an injectable writer and non-Node console fallback), so measurements stay visible under the default reporter without every author rediscovering raw `process.stderr.write` or changing global reporter behavior
- make the deliberately build-free `test:unit` loop distinguish stale `dist/` from a real failure: postbuild records a bounded deterministic SHA-256 over sorted `src/**`, and the unit wrapper warns (without skipping or failing) when the marker is missing, invalid, or no longer matches, pointing to `test:src`/`build:src`
- make packaged-SPA acceptances fail at the missing-build precondition with an explicit `npm run build` remediation instead of misreporting the absent `dist/dashboard/index.html` as an unexplained `/dash/` `404 !== 200`; the check remains a failure, never a skip
- split the 2,299-line SessionInventory implementation into focused contract, approved-root scanner/descriptor-safe JSONL parser, authenticated persistence codec, and bounded query/search/cursor modules behind the exact existing public API and persisted format, leaving request-path inventory reads filesystem-free
- degrade `adapterReadiness` when a real call fails authentication, instead of reporting green from credentials that are merely configured: a host answered `ready: true` with 53 authenticated models while every turn failed 401, because the count tested `hasConfiguredAuth` rather than any working call. A turn ending in an authentication error now records `call_auth_failed` and clears `ready`, and a turn that succeeds clears it again so the signal recovers rather than latching. The classifier deliberately ignores rate limiting, quota, and content filtering, since reporting a credential problem for a healthy host is the same wrong answer in the other direction
- refuse an unresolvable model at `open` instead of substituting one. The integration guide promised that a client naming a provider the instance has no entry for is refused at `open` rather than at `wake`; it was not. An unknown pair fell through to the first available model and the auth check then tested the substituted provider, so it passed. Measured rather than reasoned about: a session opened with `no-such-provider/no-such-model` bound to `anthropic/claude-fable-5`, meaning a typo would have answered plausibly on a model the client never named, with no error at `open` and nothing in any response to reveal it
- report the model a session is bound to in `status`, read from the live session rather than echoed from the open request, so a consumer can confirm which model answered instead of scanning the event stream. The adapter seam is optional, so credential-free fakes keep working and a snapshot omits the field rather than failing when a session is disposed
- close a hole in the lockfile prefetch guard, and name the class: it selected entries having a `resolved` URL and then asserted those entries carry `integrity`, so an entry with neither fell outside the guard entirely. A regenerated lock produced exactly that during the SDK migration — workspace packages recorded with neither field — which passed the guard and failed inside `nix build` as ENOTCACHED after a multi-minute dependency refresh. The guard now selects by location and asserts both fields, with a negative control that fails if the selector is narrowed back. A guard whose selector is derived from the field it validates cannot detect that field's absence, and unusually for this family the smell is greppable: the selector mentions the same field as the assertion
- name a third negative-control failure, distinct from a vacuous assertion and a misaimed one: an assertion that fails correctly while its failure text advises the wrong response. That text renders only on the failing path, so a green suite is no evidence about it, making it simultaneously the most likely to be wrong and the least likely to be read. The `getDefaultSessionDir` drift alarm told its reader to update the constant and consume the upstream export, which is the one response that satisfies the alarm and leaves unasked the question it exists to force. Fire the assertion once and read what it prints
- migrate to Pi SDK 0.82.1, which clears the protobufjs advisory: measured on the resulting lockfile, `npm audit` no longer reports the moderate protobufjs finding for 7.5.0-7.6.4, because the SDK now resolves 7.6.5; the pre-existing high brace-expansion finding is unchanged. `AuthStorage` is no longer exported and `ModelRegistry` is replaced by an async `ModelRuntime`, so the factory now builds its runtime once behind a promise and reports `model_runtime_initializing` rather than asserting zero available models while it is still building — unavailable and empty are different answers. The session-scoped `AuthStorage` clone that carried an environment overlay becomes a credential-store overlay whose type is derived from the SDK's own option type, so a future change to that contract fails the build instead of diverging silently
- take the new session events and RPC command the pinned unions revealed rather than making them compile: re-deriving the contract found four added events and `get_available_thinking_levels`, whose absence had turned the controller's exhaustive switch into a function with a missing return, and the command is now implemented, validated, and carried through the schema, capabilities fixture, and conformance fixture
- keep spawned commands free of Pi session identity: SDK 0.82 defaults `exposeSessionEnvironment` to true, injecting `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, and `PI_MODEL` into every bash command's environment, which hosted sessions never opted into; the host's environment-overlay bash tool sets it false explicitly
- make the documented shrinkwrap-integrity repair a supported command instead of a manual step: `npm run lock:repair-integrity` restores the three nested Pi workspace packages' integrity from the registry's own published value for the exact name and version already named by the entry, cross-checking against another lock entry for the same tarball where one exists and refusing on disagreement, and `:check` fails without rewriting

- require every quoted figure to come from the run it describes, in a report or in passing, and to be captured in the invocation that produces the result rather than transcribed — a report lends a fabricated number the credibility of the checkable material around it, and a passing mention is likelier to contain one
- hold the `@smoke` browser subset to bounding only what the fixture determines, since it gates every push: times, pixel geometry, and scroll offsets are rejected there while rendered-row counts stay allowed, and fixing the camelCase blind spot this exposed also widened the existing wall-clock rule to catch names like `totalDuration`
- route every path mode check through the tested exposure predicate, completing the pair: the 40 open-coded `(info.mode & 0o077) !== 0` comparisons now call `hasForbiddenExposure` with the policy they always applied, the TLS module keeps choosing per path between its certificate and its key, the three authority-to-act checks correctly gain no mode requirement at all, and the suite fails if any module masks a mode itself or changes the policy recorded for it
- pin the mode half of path checks as its own axis rather than a restatement of ownership: an exposure policy distinguishing material nobody else may read from material others may read but not modify, a combined trust policy in which exposure is optional so authority-to-act checks keep taking no view on mode, and a census of every mask literal so widening one is a visible diff
- record the measurement form of vacuity in CONTRIBUTING's negative-controls section — counting outcomes tells you the distribution of what happened, not whether the thing you are counting is capable of happening — along with the two ways restoring a manual mutation goes wrong, and the distinction between a guard that verifies nothing and one pointed at the only value its own caveat exempts
- restore CI to dispatching jobs at all: an unschedulable macOS job — no registered runner carries its labels — held the whole workflow's concurrency group once cancellation was scoped to pull requests, so every run after that change waited behind a run that could never complete and reported nothing.
