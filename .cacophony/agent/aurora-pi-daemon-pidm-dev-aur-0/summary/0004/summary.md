## Before state

- The adapter descriptor already required explicit `maxConcurrentRequests` and `maxQueuedRequests`, but there was no negotiated reviewed starting point for normal parallel Pi tool traffic.
- When active plus queued capacity filled, the runtime returned a retryable capacity error but exposed no retry hint and no capacity/occupancy/high-water/rejection/saturation/per-method telemetry.
- Operators had to infer the queue from a Dashboard error. Daemon status, Session API resources and Dash session information could not distinguish a genuinely saturated queue from leaked/stale capacity.
- Existing tests covered a tiny 1-active/1-queued refusal but not realistic bursts, retry with the same idempotency key, active timeout, teardown accounting or cross-session isolation.

## After state

- Exported/negotiated `HOST_TOOL_ADAPTER_RECOMMENDED_QUEUE_LIMITS` names a reviewed 4-active/16-queued starting point while preserving the descriptor as the only actual authority; Pi Daemon never silently overrides caller policy.
- Genuine hard-capacity refusal still occurs before an invoke frame is written, remains retryable, and carries a bounded `retryAfterMs` hint. Retrying the same semantic operation preserves the original idempotency key. Active timeout stays indeterminate and emits one targeted abort, never replay.
- Each exact session generation reports content-free live telemetry: configured capacity, current occupancy, active/queued high-water, accepted/completed/failed/rejected/cancelled/timed-out counts, fixed last-refusal reason, saturation count/total/longest duration, and per-operation queue-wait/request-latency summaries.
- Telemetry is generation-fenced and cloned through `SessionAdapter`, multiplexer host/session status, negotiated Session API resources/capabilities, framed RPC ready resources and embedded/remote Dash session information.
- Dash InfoPane renders occupancy/capacity, high water, outcomes, saturation, fixed refusal reason and per-operation timing. No payload, path, request/idempotency key, endpoint, capability, response, environment value or error text enters telemetry.
- Realistic 18-request bursts drain through 2-active/16-queued without loss. Hard maximum refusal/retry, active timeout, cancellation, session disposal and independent-session progress are deterministic tests.
- Public JSON schema, fixtures, generated Android protocol metadata, operations/security/session/tool-adapter docs and plans are synchronized.
